## 1. How this was verified (not just read)

- Built a Go 1.26.8 toolchain from source (the sandbox had 1.24) and ran `go build ./...` and `go vet ./...`: **clean**.
- `go test -count=1 ./...` with outbound network deliberately broken (bogus `HTTPS_PROXY`, empty `NO_PROXY`): **all 35 packages pass in 28 s**, which proves the unit tests are offline as the brief demanded.
- Release-style build (`CGO_ENABLED=0 -trimpath -ldflags='-s -w'`): **10.7 MB** (budget 15 MB); `go.mod` has **6 direct modules** (budget 6).
- Offline demo (`testdata/demo-repo`, committed cache): human and SARIF output correct; SARIF declares the 2.1.0 schema, 16 rules, findings on `package-lock.json:32`.
- Live run from the sandbox against `registry.npmjs.org`: `trustdiff check npm:event-stream@3.3.5` reproduces the README verdict (TD002 block: `right9ctrl` published none of the previous 5 versions; TD003 warn). OSV, deps.dev and `api.npmjs.org` were unreachable from the sandbox; every affected check reported `skipped` with the reason and the exit code was still 1 from TD002 — the degradation story holds.
- Three independent code reviews (engine; lockfiles/doctor/report; CI/release/docs), then every High finding below was confirmed by reading the cited lines.
- Live artifacts: releases v0.0.1–v0.4.0 exist; v0.4.0 has 16 assets (6 archives, 6 SPDX SBOMs, `checksums.txt`, `checksums.txt.sigstore.json`, 2 source archives); 5 SLSA provenance attestations (one per tag, signer `release.yml@refs/tags/vX`); npm `@trustdiff/bun-scanner` 0.4.0 and 0.4.1 published (0.4.1 via GitHub Actions with `dist.attestations`, zero dependencies); `vahapogut/homebrew-tap` and `vahapogut/scoop-bucket` exist with the generated files; all 12 `uses:` in workflows are 40-hex SHAs and 8 of them were checked against their tags and match; no secrets in the tree or history; `docs/demo.gif` present (201 KB, 1200×700).

## 2. Verdict in one paragraph

The engineering quality is far above what the size and the 40-hour timeline would suggest: the parsers mirror the real lockfile grammars and carry correct line numbers, the HTTP layer is a single bounded choke point (size caps, atomic cache writes, capped decompression, no extraction to disk), `--fix` is atomic and refuses anything it cannot rewrite safely, the policy loader is strict three ways, the supply-chain posture of the repo itself (SHA pins, least privilege, OIDC publishing, cosign + SBOM + provenance that really exist) is better than most established projects, and the documentation is unusually honest. The real problems sit at the seams between components, and several of them defeat the gate on exactly the inputs it exists for: packages the registry does not know skip the lockfile-only checks, a same-version integrity swap is detected and then thrown away, a plain `requirements.txt` yields nothing to evaluate, one of two advisory sources being down turns into a clean pass, and `prepare` is counted as an install script (false blocks). None of these is hard to fix; all of them need a test that pins the scenario.

## 3. Findings to fix, in priority order

Severity: **P0** = the gate passes something it should have caught; **P1** = false blocks / wrong data that erodes trust; **P2** = `doctor --fix` can damage a valid config; **P3** = integrations, CI, docs.

### P0 — silent passes

**F1. Lockfile-only checks never run for a package the registry does not know.** `internal/checks/runner.go:372-375`: when `Versions()` returns `registry.ErrNotFound`, `load()` returns early and the caller skips *every* applicable check, including TD013 (exotic-source) and TD014 (integrity-missing), which read only the lockfile entry. Scenario: a PR adds `"evil-lib": "git+https://github.com/attacker/evil-lib.git#<sha>"` (or any private/unpublished name); npm 404s; the report says "skipped: not found in the registry" for all checks and the exotic-source check whose purpose is non-registry packages never fires. `internal/cli/diff_test.go:527` only covers a name the fake registry knows. Fix: give `Check` a capability flag (e.g. `NeedsRegistry() bool`); in `evaluate`, run lock-only checks even when `load()` returned a skip reason. Test: a lockfile with a git-sourced name that the fake registry 404s → TD013 block.

**F2. Same-version integrity / resolved change is detected and then discarded.** `internal/gitdiff/diff.go:109-111` correctly classifies an entry with the same version but a different `Integrity`/`Source`/`Resolved` as `Changed`, but `internal/cli/diff.go:172-177` forwards only `BaseVersion`; no check receives `Change.Base`, and nothing compares hashes (TD014 only tests emptiness). Scenario: PR keeps `lodash@4.17.21` but swaps `integrity` for the hash of another tarball, or repoints a git entry to another repo → evaluated, all checks pass, exit 0. Fix: add **TD016 `lockfile-entry-changed`** (default block) fed with the base entry: "same version, integrity changed from X to Y / resolved changed from A to B". Document it in `docs/checks.md`, add the rule to SARIF, bump the report schema additively. Test: `diff_test.go:112-143` currently asserts only the `Changed` classification; assert the finding.

**F3. Duplicate-version collapsing hides a tampered nested copy.** `internal/gitdiff/diff.go:146-168` (`normalize`) and `internal/cli/lockfiles.go:151-168` (`entryInputs`) keep only the first entry per (ecosystem, name, version). Scenario: top-level `node_modules/lodash` is clean; the PR edits `node_modules/foo/node_modules/lodash` (same version) to `resolved: https://evil.example/lodash.tgz` with no integrity → collapsed into the clean copy → no change, no TD013/TD014, in both `diff` and `scan`. Fix: collapse only when Source/Integrity/Resolved are identical; otherwise keep each divergent copy with its own line. Test: nested duplicate with a divergent resolved URL → TD013 on the nested line.

**F4. Advisory checks pass when one of two sources is down.** `internal/checks/td009.go:62-88` and `td011.go:121-128`: OSV down + deps.dev reachable and clean → `return Result{}` → the check lands in `evaluated`, `Unavailable` stays false, `on_data_unavailable: fail` never fires, and the report carries no trace that OSV was unreachable. `td009_test.go:150-154` enshrines this. Fix: when a source was an outage (not a definite answer) and the surviving source found nothing, return `Skip` with the outage reason; findings from the live source still win when present. Related plumbing: (a) `internal/checks/loader.go:154-167` stores the error for *all* refs although `osv.Advisories` returns answered refs plus a `*PartialError` (`osv.go:319-326`) — use `errors.As` and store errors only for `partial.Refs`; (b) facet-level outages (`crates.go:344-348` archive download, `pypi.go:192-196` integrity 5xx) become `VersionInfo.Unknown[...]` and `Subject.outageReasons` (`check.go:131-140`) reads only `s.Unavailable`, so they bypass `on_data_unavailable` — classify them as outages too. Tests: "OSV outage + deps.dev clean → skipped TD009/TD011"; partial OSV failure only poisons the failed refs; facet outage + `fail` → exit 3.

**F5. `requirements.txt` without `--hash` yields zero entries.** `internal/lockfile/pipreq/pipreq.go:374-378` drops every unhashed pin with a note. The most common file shape (`requests==2.31.0`) therefore produces nothing to evaluate: TD014 (the check that should say "no hash") can never fire for pip, and TD001/TD008/TD009/TD010 never see a newly added pin. The package comment's justification (pip refuses unhashed lines once one line has a hash) only applies to mixed files. Fix: emit the entry with empty `Integrity` and let TD014 report it. Test: unhashed pin → entry with TD014 warn.

### P1 — false blocks and wrong data

**F6. `prepare` counted as an install-time script → TD005 false blocks.** `internal/registry/npm/npm.go:146`: `installScriptNames = {"preinstall","install","postinstall","prepare"}`. npm runs a dependency's `prepare` only for git/local dependencies, never for a registry tarball (npm's own `hasInstallScript` excludes it). Many published packages retain `"prepare": "husky"` or `"npm run build"`, so a release that merely adds a husky hook triggers TD005 at block level. Fix: drop `prepare` from the set (optionally record it under a separate evidence key at info level). Test: a release that adds only `prepare` → no TD005.

**F7. TD007 ignores the version the project actually had.** `internal/checks/td007.go:104-125` compares only with `s.Previous`. A PR bump 1.0.0 → 1.2.0 where 1.1.0 introduced `plain-crypto-js` reports nothing — the Axios pattern the check cites. TD005 already does the two-way comparison (`td005.go:66-79`); mirror it in TD007 (and TD004). Test: three-version fixture with the dependency introduced in the middle version.

**F8. TD008 measures edit distance on the full scoped name.** `internal/typosquat/rules.go:98-110` compares the whole canonical name and `distance.go:8-13` raises the threshold to 2 once the popular name is ≥10 runes — which every scoped name is — so the shared scope contributes zero distance and bare names only need to be within 2 edits. Simulated against `internal/lockfile/npm/testdata/superset-frontend-package-lock.json`: 9 of 189 non-popular names flagged, all legitimate (`@loaders.gl/wms`→`@loaders.gl/gis`, `@types/d3-cloud`→`@types/d3-chord`, `@types/rison`→`@types/bson`, `rison`→`jison`, `lz4js`→`lz4`, `webpack-visualizer-plugin2`→`…-plugin`). At block level that fails the gate on ~0.4 % of a large lockfile. Fix: for scoped names apply the fuzzy rules to the bare name with `Threshold(bareName)` and require the same scope (cross-scope look-alikes stay `RuleScope`'s job); consider requiring a popularity gap (popular target ≫ candidate downloads) before block. Add a **precision test** over the Superset fixture next to `recall_test.go` (currently recall-only).

**F9. Registry canonical name is promised but never adopted.** `internal/registry/registry.go:30-36` says callers adopt `VersionList.Name` before asking OSV/deps.dev; `runner.go:372-380` keeps `s.Ref` as typed. `trustdiff check cargo:Serde` or `cargo:serde-json` evaluates the crate but queries OSV/deps.dev/downloads for a package that does not exist → advisories silently clean. Fix: rewrite `s.Ref.Name = list.Name` (memo keys included) before advisory lookups, or reject non-canonical spellings with exit 2.

**F10. Base-version fetch failure poisons `SourcePrevious`.** `runner.go:471-477` stores a base-version error under `SourcePrevious` when unset, so `previousUnavailableSkip` skips TD003/TD004/TD005/TD007 although `s.Previous` loaded fine (e.g. the base version was unpublished). Fix: a separate `SourceBase` key consulted only by the base-aware comparisons.

**F11. Version downgrades are invisible.** A `Changed` entry with `Base > Head` is evaluated like an upgrade; a merely older version passes silently (TD010 still catches a known-vulnerable target). Consider a downgrade signal via `version.Compare` (info level) or fold it into TD016.

### P2 — `doctor --fix` can damage a valid configuration

**F12. Deno `minimumDependencyAge`: valid forms judged wrong; `--fix` deletes the `exclude` list.** `internal/doctor/rules_deno.go:38` uses `Unit: ISO8601`; `desired.go:84-88` calls `Unit.Parse`, which requires the `P` prefix. Deno's docs accept an ISO-8601 duration, a number of minutes (`4320`), an absolute date/RFC 3339 timestamp, `0`, and the object form `{"age": "P3D", "exclude": [...]}`. Today `4320` → *wrong*; the object form has `v.Text == ""` → *wrong*; and `configfile/json.go:108-118` marks a map value editable, so `--fix` replaces the whole object with `"P3D"`, silently dropping `exclude`. Fix: a Deno-specific desired-value judge that accepts minutes and absolute dates, reads `age` out of the map, and refuses to overwrite a map. Tests: numeric, object and RFC 3339 forms.

**F13. uv `exclude-newer` absolute timestamp overwritten.** `rules_python.go:39`, `units.go:107-115`: uv accepts RFC 3339 timestamps; `wordUnit.Parse("2026-06-01T00:00:00Z")` errors → *wrong* → `--fix` replaces a deliberate, stronger point-in-time pin with `"3 days"`. Fix: compare absolute dates against `Params.Now` (set if `now - date >= cooldown`) and never rewrite one.

**F14. Yarn `npmMinimalAgeGate` string form.** `rules_yarn.go:23-43`, `docs/doctor.md:141`: the code says durations like `3d` are read from 4.11; the brief says strings were silently ignored on 4.10–4.14 and accepted from 4.15 (PR #7135 made `1d` the default). Verify against the Yarn release notes and make the judge version-aware: `"3d"` on a version that parses it is *set*, not *wrong*, and must not be rewritten to `4320`.

**F15. `strict-allow-scripts=true` is auto-written.** `rules_npm.go:52-70` (Fixable, warn). With no `allowScripts` in `package.json` this turns the npm 12 warning into a hard error for every native dependency and can break `npm install`. Write it only when `allowScripts` exists; otherwise report it as advice like `allowBuilds`.

**F16. The project itself is reported as an exotic, hash-less dependency.** `internal/lockfile/uv/uv.go:124-127` drops `virtual = "."` but keeps `editable = "."` (fixture `uv-docker-example.uv.lock:710`), `cargo.go:178-181` keeps workspace members, `poetry.go:407` similar → TD013 info + TD014 warn on the project's own name (ripgrep: 10 warns on unmodified upstream). Drop the root project like `virtual`; consider exempting `SourcePath` from `integrity-missing` the way TD013 caps it at info.

**F17. SARIF `uri` not repo-root relative for `scan <subdir>`.** `internal/cli/scan.go:29,88`, `report/sarif.go:258`: `scan frontend --format sarif` writes `package-lock.json`, which code scanning resolves against the checkout root. `diff` is correct. Resolve against the git root when inside one (or emit `originalUriBaseIds`).

**F18. pnpm DR011 `strictDepBuilds` default-since.** `DefaultSince: "11"` vs pnpm docs stating "Default: true, Added in: v10.3.0". Verify; if the default was true since 10.3, pnpm 10 projects are wrongly told to write it.

### P3 — integrations, CI, docs

**F19. Bun scanner is fail-open by default.** `integrations/bun-scanner/src/index.ts:571-579`: a missing `trustdiff` binary prints one stderr line and returns `[]`, so `bun install` (CI included) proceeds as if clean unless `TRUSTDIFF_BUN_REQUIRE_BINARY=1`. `README.md:262` promises the opposite ("an install where nothing could be checked should not look like an install where nothing was wrong"). Fix: default to require-binary when `CI` is set (or always), or return a `warn` advisory on the first package so Bun prompts on a TTY and cancels in CI; reword the README. Also `index.ts:465-485` iterates `report.subjects` only — a planned ref missing from the report reads as clean; report it as unchecked.

**F20. Pre-commit hook covers 4 of 9 lockfile formats.** `.pre-commit-hooks.yaml:28` lists only `package-lock.json|pnpm-lock.yaml|uv.lock|Cargo.lock`; line 5 still shows `rev: v0.2.0`. A `yarn.lock`, `bun.lock`, `deno.lock`, `poetry.lock` or `requirements*.txt` change never triggers the gate. Extend the regex to the parser list and bump the example rev.

**F21. `action.yml` is not exercised on any OS.** `.github/workflows/selftest.yml:5-9` uses `go run` and its header refers to a self-test that never landed. The component that runs with other people's tokens is untested; the Windows path (`$RUNNER_TEMP` backslashes, the `unzip`-or-`tar` fallback at `action.yml:291-298`, where Git Bash's GNU tar cannot read zips) is unverified. Add a workflow that runs `./` (local action) on ubuntu/macos/windows against `testdata/demo-repo`, once with an explicit `version` so the cosign path is covered.

**F22. README action example uses a mutable tag that `doctor` itself flags.** `README.md:292`: `uses: vahapogut/trustdiff@v0.4.0` is a tag; DR110 (`scan_actions.go:157-162`, warn, `ci_min_severity: warn`) reports it, so a repo following the README fails `doctor --ci` on its own workflow. Show `uses: vahapogut/trustdiff@<40-hex> # v0.4.0` pointing at the post-release "pin and checksums" commit, or maintain a moving major tag advanced to that commit. Also `README.md:304` says the action verifies "against checksums signed with cosign"; the default-version path (`action.yml:142-166`) is a sha256 compare against the embedded table and never invokes cosign — word it precisely.

**F23. Third-party notices not shipped; CONTRIBUTING contradicts the tree.** `.goreleaser.yaml:66-72` packs only LICENSE and README, but the binary embeds the MIT-licensed npm-high-impact list and the CC-BY-4.0 PyPI list (`internal/typosquat/data/*.txt`) and `internal/textdiff/diff.go` is a BSD port (`LICENSE-go`); MIT/BSD require notice reproduction. `CONTRIBUTING.md:111` says third-party Go code is never copied in. Add `THIRD_PARTY_NOTICES` to `archives.files`; amend CONTRIBUTING.

**F24. CI hardening nits.** `.github/workflows/demo.yml:50-57,85-157`: `contents: write` + `persist-credentials: true` are live while vhs-action fetches unpinned vhs/ttyd/ffmpeg builds and `apt-get install` runs, then the job pushes directly to the dispatched branch with a hard-coded human `--author` — push to a bot branch and open a PR, obtain the token only in the final step. `.github/workflows/npm-publish.yml:229-231` interpolates `${{ steps.decide.outputs.* }}` inline in `run:` against the repo's own "everything through `env:`" rule (not exploitable today; fix anyway). `release.yml:40-41` floats `go-version: "1.26.x"` with `check-latest: true` while `SECURITY.md:53` claims byte-for-byte reproducibility — pin the exact version (or `go-version-file` + `GOTOOLCHAIN=local`). The cosign identity is `release.yml@refs/tags/v*`, so anyone who can push a `v*` tag is the trust root — add a tag ruleset restricting `v*` creation and a GitHub Environment with a required reviewer on the release job.

**F25. Smaller engine nits.** `httpcache.go:52` + `client.go:272-313`: a fixed 10 s per-attempt timeout includes the body, so a 30 MB packument on a slow link times out four times and every check for that subject is skipped — use `ResponseHeaderTimeout` plus a body deadline scaled to `Content-Length`. `httpcache.go:254`: no `CheckRedirect`; cross-host redirects are followed and cached under the original host — restrict to same host (plus `static.crates.io`). `npm.go:282,364`: raw name concatenated into the downloads URL while `ref.go:37` rejects only space/tab/backslash — validate against npm's name grammar. `npm.BulkDownloads` (`npm.go:313`) is never used, so `scan` pays one downloads request per package. `jsr.go:396` uses the wall clock instead of `TRUSTDIFF_NOW`. `--jobs` help says "registry requests" but bounds subjects. `scan_actions.go:221-231`: DR110 scans `.github/workflows/*.yml` only, not `runs.steps[].uses` in composite `action.yml` files. `units.go:91-96`: pip's `uploaded-prior-to` is documented in days (`P3D`); `PT12H` for a sub-day cooldown may be rejected — round up to whole days. `npm.go:307`: `devOptional` → `Dev: true` mislabels a package reachable through an optional edge. `schema/report.v1.json:93` says npm names are "lowercase" but `NormalizeName` deliberately keeps case. `td007.go:19-21` claims an allow entry can cover one new dependency, but `runner.go:309` matches the subject ref and drops the whole result — match TD007 allow patterns against the `dependency` evidence or fix the doc. Tap README says the v0.4.0 cask/manifest were committed by the workflow while `docs/releasing.md:296-306` says they were hand-committed — say so, or push a patch release so the job overwrites both. `CHANGELOG.md:166` link style; `LICENSE:190` appendix placeholder; `attest-build-provenance` `subject-path` omits the SBOMs (low impact, they are inside the signed checksums).

## 4. Verified good — do not regress

- `internal/checks/loader.go:485-524` `memo.do`: in-flight sharing, error memoisation and the abandoned-entry retry on caller cancellation, each with a test.
- `internal/registry/crates/archive.go`: size cap before download, body cap, SHA-256 verification, capped decompression, manifest cap, no extraction to disk.
- `internal/advisory/osvindex` (`build.go`, `read.go`): bounded zip reading, deterministic shards, asymmetric handling of unparsable range bounds to avoid false negatives. OSV client: chunking at 1000, per-query `page_token` pagination with a page cap, MAL fallback from the batch entry, identical withdrawn-record handling online/offline.
- `internal/httpcache`: sha256 keys with request-match check, atomic writes, 404 TTL cap, Retry-After clamp, size cap, one choke point for every network call.
- Policy loader: `KnownFields` + `Validate` + JSON Schema; unknown keys are errors.
- Baseline `Added`/`Rewritten` detection (`td003.go:223-241`): refusing to trust a record the change under review wrote.
- Lockfile parsers: package-lock v2/v3 (aliases, links, bundled, git, file), pnpm v6/v9 (peer-suffix keys, multi-document), yarn berry (aliases, patch locators, multi-descriptor keys), bun.lock (JSONC blanking that preserves offsets), deno v4/v5, uv/poetry/cargo `[[package]]` line placement via a string-aware `TableFinder`, requirements continuation/comment/marker handling — line numbers correct in every format.
- `--fix`: temp + fsync + rename in the same directory, refuses symlinks, keeps mode/BOM/CRLF, one backup per file with `O_EXCL`, idempotent via `holds()`, refuses anchors/merge keys/flow collections/env-interpolated INI values.
- SARIF: `$schema`, `version`, driver name/version/rules, `ruleId`/`level`/`message.text`/`physicalLocation`, region omitted for line 0, forward-slash percent-encoded URIs, clock-free `partialFingerprints`, validated against the vendored 2.1.0 schema. Markdown escapes `|`, `\`, markup and newlines.
- Verified doctor rows against official docs: npm `min-release-age` days/≥11.10, `allow-git`/`allow-remote` none in 12, `strict-npmrc`; pnpm `minimumReleaseAge` minutes/10.16/default 1440 since 11, `blockExoticSubdeps` 10.26, `trustPolicy` 10.21, `allowBuilds` 10.26, `onlyBuiltDependencies` removed in 11; Bun seconds/1.3; Poetry `solver.min-release-age`/2.4; Dependabot 3-day default; uv relative/ISO forms; Renovate words.
- Repo posture: all `uses:` SHA-pinned and correct, least-privilege permissions, `id-token: write` only in release/npm-publish, no `pull_request_target`, OIDC-only npm publishing with staging, cosign keyless + SBOM + provenance present on live releases, `preflight.fail_on_error`, template-guarded `TAP_GITHUB_TOKEN`, clean secret scan.

## 5. Suggested order of work

1. **v0.4.1 — the gate (F1–F8, F9–F11 if cheap).** Each fix ships with the scenario test named above. Add a `testdata/regressions/` directory with one fixture per finding so the incident stays pinned.
2. **v0.4.2 — `doctor --fix` safety (F12–F18).** Rule: a value the manager accepts is never *wrong*, and `--fix` never rewrites a value it did not judge *missing* or a unit it could not parse with certainty; add table tests with every accepted spelling per manager.
3. **v0.5.0 — integrations and CI (F19–F25).** Fail-closed Bun scanner in CI, full pre-commit coverage, an action self-test on three OSes, THIRD_PARTY_NOTICES, pinned Go version in releases, tag ruleset + environment reviewer.

Process reminders that still apply from the brief: re-verify every package-manager fact against the official docs before changing a doctor rule and put the date in the comment; no new dependencies without asking; no network in unit tests; conventional commits, one concern per commit; CHANGELOG entry and tag per release.
